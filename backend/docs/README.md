# 后端文档目录

本目录用于存放后端项目的各类文档，包括版本说明、依赖变更、源码解读、学习笔记等。

## 📁 目录结构

```
docs/
├── changelog/          # 版本说明文档
│   └── README.md       # 版本说明索引
├── dependencies/       # 依赖包变更说明
│   └── README.md       # 依赖变更索引
├── source-code/        # 源码逐行解读
│   └── README.md       # 源码解读索引
├── notes/              # 学习笔记
│   └── README.md       # 学习笔记索引
└── insights/           # 学习心得
    └── README.md       # 学习心得索引
```

## 📚 文档类型说明

### 1. changelog/ - 版本说明

记录后端项目的版本更新历史，包括：
- 版本号变更记录
- API 变更说明
- 新功能说明
- Bug 修复记录
- 性能优化说明
- 数据库迁移说明
- 破坏性变更说明

**文件命名规范**：`v{版本号}.md`（如：`v1.0.0.md`、`v1.1.0.md`）

### 2. dependencies/ - 依赖包变更说明

记录依赖包的变更情况，包括：
- 新增依赖包及其用途
- 升级依赖包的原因和影响
- 移除依赖包的原因
- 依赖包版本冲突解决
- 依赖包安全更新
- 依赖包性能影响分析

**文件命名规范**：`{日期}-{变更类型}.md`（如：`2024-01-15-upgrade.md`）

### 3. source-code/ - 源码逐行解读

对后端源码进行详细的逐行解读，包括：
- 控制器实现原理
- 数据模型设计说明
- 路由配置详解
- 中间件实现机制
- 认证授权流程
- 错误处理机制
- 数据库操作优化

**文件命名规范**：按模块或功能命名（如：`authController.md`、`userModel.md`）

### 4. notes/ - 学习笔记

记录开发过程中的学习笔记，包括：
- 技术栈学习笔记（Express、TypeScript、MongoDB 等）
- 框架使用技巧
- 数据库设计最佳实践
- API 设计规范
- 安全防护措施
- 性能优化技巧

**文件命名规范**：按主题命名（如：`express-middleware.md`、`mongodb-optimization.md`）

### 5. insights/ - 学习心得

记录项目开发过程中的思考和心得，包括：
- 架构设计思考
- 技术选型理由
- API 设计经验
- 数据库设计心得
- 开发经验总结
- 踩坑记录
- 未来优化方向

**文件命名规范**：按主题命名（如：`api-design.md`、`database-design.md`）

## 📝 文档编写规范

1. **使用 Markdown 格式**：所有文档使用 Markdown 编写
2. **添加目录**：长文档需要添加目录导航
3. **代码示例**：代码示例需要标注语言类型
4. **保持更新**：及时更新相关文档
5. **版本关联**：重要变更需要关联到对应的版本说明
6. **API 文档**：API 变更需要同步更新 API 文档
